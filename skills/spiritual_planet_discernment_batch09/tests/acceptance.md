# Batch 09 验收标准

## 经文上下文
- 经节、段落、全书、文体、说话者和受众齐全；
- 单节不得直接建立完整教义；
- 应用必须经过原始意义与正典位置；
- 主要替代解释必须列出。

## 原文
- 记录文本版本；
- 词法、形态、句法、语义域和语料；
- Strong编号不替代释经；
- 禁止词根谬误和所有词义叠加；
- 文本异文不得被隐藏。

## 神学
- 救赎历史不跳过原始意义；
- 教义分D1/D2/D3；
- 宗派范围和共识等级明确；
- 历史神学尽量使用一手来源；
- 次要观点不得作为得救测试。

## 引文与权利
- 引文有作者、作品、版本和定位；
- 不杜撰页码；
- 二手引文不得冒充一手；
- 每个来源有rights_status；
- 禁止未经授权全文嵌入和导出。

## 经文误用
- 检测断章取义、文体错误、听众转移和词义谬误；
- 检测成功神学、滥权、责备受害者和反专业帮助；
- 检测结果是风险提示，并允许人工复核。

## RAG
- 混合检索与来源质量权重；
- 反证和限定性证据必须检索；
- 每个生成陈述可追踪到Claim与Passage；
- 无证据时必须返回insufficient_evidence；
- 高影响教义和牧养应用支持人工复核。

- 12个Knowledge Packs；
- 20个Runtime Skills；
- 11个Schemas；
- pytest全部通过；
- Checksum和ZIP完整；
- 证据图谱记录模型、Prompt、版本与人工修订。
