# Batch 06 验收标准

## 教义完整性
- 10 个 Pack 全部可加载；
- 完整路径含创造、罪、律法、基督、称义、收纳、联合、成圣、教会、终末；
- 基督、十架和身体复活不可省略；
- 称义根据必须是基督，不是行为；
- 成圣必须是果子而不是称义基础；
- 终末必须包含复活和新创造。

## 个性化
- 能按能力称义、控制、道德自义、受害、群体和属灵骄傲选择切入点；
- 同时保留真实受苦与结构因素；
- 支持 brief、standard、deep；
- 支持 seeker、christian、unknown、other；
- 支持教会伤害与宗教强迫路径。

## 律法—福音
- 不只给命令；
- 不只给安慰；
- 律法显罪后必须转向基督；
- 福音之后包含悔改、信心和新顺服；
- 行动计划明确标记不是赚取接纳。

## 宗派治理
- Tier 1 可作为共同核心；
- Tier 2 必须标记传统范围；
- Tier 3 不得作为得救测试；
- 不用洗礼、千禧年或恩赐细节取代福音核心。

## 安全
- 用户拒绝时停止推进；
- 宗教强迫优先称义、收纳和确据；
- 虐待情境不强迫恢复接触；
- 不许成功神学式健康财富保证；
- 不判断具体个人最终得救状态。

## 工程
- pytest 全部通过；
- Schema 全部可解析；
- Pack ID 无重复；
- Checksum 与 ZIP 完整；
- Trace 包含 Pack 版本、同意、教义层级和质量门。
