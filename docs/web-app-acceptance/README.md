## 覆盖口径

本套件共 **703 条用例**。其中 **198 条业务与跨平台场景**，以及 **505 条按源码条目展开的用例**，后者含 100 位数字人的独立问答。测试范围按用户可到达的界面、独立路径、业务行为和权限边界建立。经文、书籍、音视频和地图地点等大型内容集合采用规则、边界及代表值覆盖，具备固定独立合同的名册和注册表逐条验收。

- 首页情绪球、自然语言查经、登录与资料、政策及删除申请、主导航、快捷方式、弹层和深链接。
- 灵修、读经与译本、背经、书籍、专题、日记与回收站、提醒、查找与数据导出。
- 代祷与分享、团契、相通与语音、主日信息、慕道班、小组、伙伴与关怀、公开问卷。
- 圣经主题地图、图层、路线、耶路撒冷沙盘、人物镜鉴、关系与形成图谱。
- 今日心镜、危机守护、属灵塑造、守心、形成孪生、数字人、统一门户、AI 门训四轨与 Batch 01–12、宣教邻舍桥和组织治理。
- 中英文、阅读顺序、字号、安全区、弱网、离线、后台与媒体生命周期、缓存隔离、角色与同意、待审内容、API 失败与并发。

Coverage 中的定位值以 Web 仓库为根，`#L` 行号对应上面的提交。App 路径以 App 仓库为根。每行先跑「逐项用例」，再对同一入口关联「业务用例」。同一份业务证据可被多个条目引用，逐项界面证据仍各自记录。「待定位」表示当前表缺少确认后的 App 落点，执行者需在目标版本登记路径或记录缺口。「待确认旧入口」包括源码中仍存在、当前 `App.jsx` 未调用的 `DevotionHubPage` 旧入口。「平台呈现待核」适用于 PWA/离线、列国默示、游戏等有不同原生呈现的流程。外部链接、内嵌页和原生屏的实际映射需在执行表记录。工具脚本、部署资产和无产品入口的源文件只在影响可观察行为时进入用例。

## 执行顺序

1. **建立对照。** 固定 Web 源提交、测试后端版本、App 安装包及其 SHA-256、两端语言、角色、开关、数据种子版本。首次查看某个界面时，先采 Web 基准截图，记录实际入口、标题、重点信息区、主要按钮和空/错误态。App 采用系统交互时，比对信息和任务结果是否等价，保留证据说明差异。
2. **优先跑 P0。** 使用匿名及登录、两个账号、两个租户。覆盖登录后的回跳、数据边界、S3 安全出口、同意、审核、危险动作、媒体释放和过期深链。P1 跑全链与显示，P2 跑保留或获确认的较低风险项目。遇 Web 已知缺陷，分别记录 Web 实测、App 实测和产品预期。
3. **跑真实路径。** 按「夹具」准备数据。UI 样例通常先在同一 Web 基线手工对照，再在 App 点击对应入口。E2E 样例通过 App 和受控后端来验收业务写入、重新打开读回与错误行为。可用 Flutter 集成测试自动化稳定步骤，并引用本表 ID。DEVICE 样例须在真实设备实际执行，模拟器证据可单独保留。
4. **核对应用状态。** 每个远程页面按 UI-19 验证加载、无记录、成功、失败与恢复。对于动作型页面，再验证提交中、重复点击、导航离开、重新进入与读回。对于无法用所在页面产生某状态的静态页，填写该项的具体理由。
5. **回归归档。** 按 Case ID、平台、构建和角色保留返回路径、截图、录屏、脱敏请求结果及关联缺陷。重测用新一行或执行批次记录，保留初次失败与重测结果。涉及权限、数据或安全的缺陷修复后，重跑使用相同服务或状态的受影响入口。

### 验收记录

初始状态统一为 `NOT_RUN`。记录时使用 `PASS`、`FAIL`、`BLOCKED`、`NOT_RUN` 或经产品确认的 `N/A_APPROVED`。PASS 须完成步骤、符合预期，并有本次执行证据；BLOCKED 写清阻塞现象、负责方、解锁条件和已采证据。平台差异或废弃入口需要确认理由及审批记录。按平台计算应跑、PASS、FAIL、BLOCKED、NOT_RUN 和已批准不适用数；P0 的未运行、失败或阻塞留在分母。供应商、实机及人工内容审批分别记录实际结果。

建议执行记录包含 Case ID、Web/App/后端提交与构建、平台/OS/设备、语言/字号/权限、夹具标记、测试开关、时间、执行人、步骤结果、实际差异、截图/录屏及脱敏 API 证据。测试日志与共享链接去除令牌、个人信息和私密原文。

| 需独立确认的执行面 | 就绪条件 |
| --- | --- |
| 原生 Android/iOS、麦克风/电话/推送、读屏 | 提供目标签名测试包及两平台实际设备，使用当前发布候选执行。 |
| 数字人真实媒体 | 测试供应商已配置，目标声音/形象及发布状态有正式记录；应分别运行失败回退和真实轨道。 |
| 主日学与高风险内容 | 版本、角色、年龄带、监护同意、S0–S3、审批与禁用场景均有测试资料；发布和人工内容结论由实际授权人给出。 |
| 深链接、政策、外链和旧入口 | 产品登记原生、内嵌、外跳或已批准移除的映射，QA 实测两端路径；空白候选逐条收敛。 |

## 交付边界与恢复

本目录包含执行指南及两张表。它使用已提交源码与 Flutter 候选文件进行离线结构核查。所有 Web/App 产品执行结果保留 `NOT_RUN`，内容维持各系统真实审批状态。本次没有数据库迁移或发布。撤销交付时可删除这个新建目录，执行前核对其中是否已有后续的 QA 记录。
