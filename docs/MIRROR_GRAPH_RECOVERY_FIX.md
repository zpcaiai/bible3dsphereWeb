# 人物图谱请求与加载恢复修复（2026-10-23）

用户明确报告“加载失败：Load failed”。该提示来自图谱 fetch.catch。旧生产构建的 API_BASE 指向 Hugging Face 跨域地址，本站已有可用 /api 代理；在真实 Chrome 阻断直连 HF 图谱请求后，页面复现“加载失败：Failed to fetch”。不宣称已确定用户设备具体是 DNS、网络拦截或其它传输故障。全新浏览器网络通畅时旧版本可以正常加载。

旧版本在真实浏览器中阻断一次 RelationshipGraphView chunk 请求后，全局错误恢复刷新到首页，不能继续打开人物图谱。首次入口的 Suspense 还会显示空白。这是另外发现并修复的恢复缺口；故障注入与普通生产访问结果分别记录。

## 改动

- `src/RelationshipGraphView.jsx`：在 holiness.uk/www.holiness.uk 固定使用现有同源 /api 代理，避免历史构建配置造成浏览器直连 HF；其它部署保留显式 API_BASE。请求失败提供实际重新请求的按钮；HTTP200 的 success:false 不再伪装为空图。授权头、查询参数、迟到响应防护均保留。
- `src/__tests__/RelationshipGraphRouting.test.jsx`：覆盖域名路由、其它部署保留配置、失败信封与重试（协议单元测试使用明确的 stub，浏览器验收仍请求真实后端）。

- `src/lazyWithRetry.js`：镜鉴页面的恢复刷新保存一次性导航标记；支持调用方指定独立重试键及第二次失败的局部错误界面。
- `src/App.jsx`：消费该标记，恢复原镜鉴/图谱入口、人物及聚焦状态；入口加载显示状态和返回按钮。
- `src/MirrorPage.jsx`：图谱子模块复用既有加载恢复机制，使用专用重试键。别的懒模块成功不会清除图谱失败标记。只自动刷新一次；持续失败显示局部错误、重试和返回。用户点击重试会主动刷新页面并保留导航，不是无刷新重试。
- `src/__tests__/lazyWithRetry.test.jsx`：验证标记保留、成功清理、不同模块隔离及二次失败返回。

没有修改人物资料、后端 API、登录/权限、审核状态、5000ms 测试限制或已有断言。无数据库迁移。外部模型/语音、真实媒体、完整登录业务及人工审核仍未完成。
